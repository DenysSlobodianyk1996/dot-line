# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Dots and Boxes" («Крапки й квадрати»): the two-player Dots and Boxes game on an NxN field. Players take turns drawing a line between adjacent dots. The first line can go anywhere; every later line must start from an existing one. A player who closes a square owns it, and whoever owns the most squares wins.

Stack: Vue 3 (`<script setup lang="ts">`), Vite, TypeScript, Tailwind CSS v4 (via `@tailwindcss/vite`, imported in `src/assets/styles.css`), vee-validate + `@vee-validate/rules`, vue-router, vue-i18n, `vite-plugin-pwa`, Nunito via `@fontsource-variable/nunito`, Pinia (installed, but `src/stores/counter.ts` is unused scaffold). SCSS is available for `<style lang="scss">`.

## Commands

- `npm run dev`: Vite dev server on **port 4200**
- `npm run build`: runs `vue-tsc --build` type-check and `vite build` in parallel
- `npm run type-check`: type-check only
- `npm run lint`: oxlint, then ESLint. **Both run with `--fix` and modify files.**
- `npm run lint-check`: oxlint, then ESLint, without `--fix` (what CI runs)
- `npm test`: Vitest run once (jsdom + Vue Test Utils); `npm run test:watch` for watch mode
- `npm run store:screenshots`: builds, serves the build and regenerates the Play Store images in `docs/store/` with Playwright (fixture games seeded into localStorage); review and commit them. Not part of `npm test` (AR-16, AR-17)
- `npm run format`: Prettier on `src/` only (no semicolons, single quotes, width 100)
- `npm run build:capacitor`: the Android app's web build (`vite build --mode capacitor`, base `/`, no PWA plugin)
- `npm run android:build`: `build:capacitor`, then `cap sync android`, then `gradlew bundleRelease` → `android/app/build/outputs/bundle/release/app-release.aab`. Needs JDK 21 and `ANDROID_HOME` (the Android SDK). Gradle reads `ANDROID_VERSION_NAME`/`ANDROID_VERSION_CODE` (defaults `1.0.0`/`10000`) and signs only when `ANDROID_KEYSTORE_FILE` (plus `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`) is set; otherwise the AAB is unsigned.
- `npm run android:apk`: a debug APK to try on a phone (`scripts/android-debug-apk.sh`: `build:capacitor`, `cap sync android`, `gradlew assembleDebug`) → `android/app/build/outputs/apk/debug/app-debug.apk`. Finds the SDK in `ANDROID_HOME`, `~/Library/Android/sdk` or `~/Android/Sdk`. The debug app id ends in `.debug`, so it installs next to the Play Store app. `npm run android:install` also installs it with `adb install -r` on a phone connected over USB with USB debugging on.
- `npm run android:open`: opens `android/` in Android Studio

Tests: specs sit in `__tests__/` folders next to the code (`*.spec.ts`) and check external behavior only (spec "Testing Decisions"). Shared helpers live in `src/test/`: `mountGamePage({ storage, deviceLanguage })` mounts the whole app at `/game` with real router, i18n and localStorage, and calling it again simulates a reload. jsdom's device language is `en-US`, so pass `deviceLanguage: 'uk-UA'` for a Ukrainian first visit. `src/test/game-page.ts` is the page driver (`startGame`, `startComputerGame`, `clickDot`, `waitForComputer`, …) and the only place that knows the board's DOM; extend it rather than querying the DOM in specs. Computer-turn specs fake only `setTimeout`/`clearTimeout` (faking `setImmediate` hangs `flushPromises`). `src/test/setup.ts` clears localStorage and unmounts after each test. Tests and helpers are type-checked through `tsconfig.vitest.json`.

CI: `.github/workflows/ci.yml` runs type-check, `lint-check` and tests on every pull request. Deployment: `.github/workflows/deploy.yml` runs the tests, then publishes to GitHub Pages on every push to `master`. It builds with `BASE_PATH=/<repo name>/` (`/dots-and-boxes/` after the rename), which `vite.config.ts` reads as Vite's `base` and the router picks up through `import.meta.env.BASE_URL`, then copies `dist/index.html` to `404.html` so history-mode reloads work. Keep asset and route URLs base-relative (no hard-coded `/…` paths in code).

Android release: `.github/workflows/android-release.yml` runs on tags `v*.*.*`. To release, `git tag vX.Y.Z && git push --tags` (or `git push origin vX.Y.Z`). The job derives `ANDROID_VERSION_NAME` (the tag without `v`) and `ANDROID_VERSION_CODE` (`major*10000 + minor*100 + patch`) with `scripts/android-version.ts` (tested in `scripts/__tests__/`; it rejects malformed tags, minor or patch above 99 and `v0.0.0`), runs type-check, lint-check and tests, then `build:capacitor`, `cap sync android`, JDK 21, decodes `ANDROID_KEYSTORE_BASE64` to `$RUNNER_TEMP` (passed as `ANDROID_KEYSTORE_FILE`), `gradlew bundleRelease`, attaches the AAB as the `app-release-X.Y.Z` artifact, and uploads it to the Play `internal` track with `r0adkll/upload-google-play` and `PLAY_SERVICE_ACCOUNT_JSON`. The keystore is deleted in an `if: always()` step. Secrets come from `scripts/android-release-wizard.sh`. The app's first release can't go through the API: upload that AAB by hand (`docs/store/publishing-checklist.md`, step 4). Promoting from internal to closed testing or production stays manual in Play Console.

PWA: `vite-plugin-pwa` in `vite.config.ts` (`autoUpdate`, Workbox precache of all build output, navigation fallback to `index.html`). It emits the Ukrainian manifest; a small plugin there adds the English one and `404.html`. File names live in `src/static/manifests.ts`, and `setLocale()` swaps the `<link rel="manifest">` href with the language. Verify with `BASE_PATH=/dots-and-boxes/ npm run build` (both manifests, `sw.js`, icons in `dist/`), not unit tests. New static assets must match the precache `globPatterns` to work offline. The privacy policy (AR-15) is not in `public/`: its source is `src/static/privacy.html`, and the `privacyPage()` plugin in `vite.config.ts` writes it to `privacy/index.html` in every build (and serves it in dev) with its "Updated" date set to the built commit's date (`scripts/privacy-updated.ts`; `VITE_PRIVACY_UPDATED` overrides it).

Android: Capacitor (`capacitor.config.ts`, app id `app.dotsandboxes`) wraps the capacitor-mode build of `dist/`. In that mode (`vite.config.ts`) the PWA plugins are off, so there is no `sw.js`, no manifests and no `404.html`, and `setLocale()` links no manifest (it checks `__CAPACITOR_BUILD__`); Capacitor bundles the files, so the app is offline from the first launch. `android/` is committed except build output, `local.properties` and keystores. Orientation is unset (any); targetSdk is in `android/variables.gradle` and must match what Play requires. Check the capacitor-mode `dist/` (no `sw.js`/manifests) and the Pages build (still has them) after touching the build.

## Architecture

- **App shell** (`src/App.vue`): a header on every screen (logo, translated game name, `ThemeToggle`, the info button that opens the rules panel, `LanguageToggle`), then `RouterView`, then the single `RulesPanel`. Its round icon buttons are `BaseIconButton` (44 px below `sm`, `shrink-0`).
- **Routing** (`src/router/index.ts`): the only route is `/game`, and every other path redirects there. Page folders expose their root component through an `index.ts` barrel (`export { default } from './Page.vue'`).
- **Game page flow** (`src/pages/dots-and-boxes/`): `Page.vue` owns a single `reactive(new DotsAndBoxesGame())` and picks the child via `<component :is>` from a computed config (`component`, `props`, `listeners`):
  - If `dotsAndBoxesGame.isGameStarted` (both players plus size > 0) is false, it renders `game-setup/GameSetup.vue`. That form has the game mode switch (Versus computer / Two players) and, in computer mode, the difficulty switch, a "You" `PlayerField` and the read-only `ComputerOpponentField`. It emits `gameSetup`, and Page applies the result with the chained setters (`setGameMode(...)` first).
  - Otherwise it renders `Game.vue`, which gets the reactive game as a prop and changes it through model methods. It shows `game/GameBoard.vue` next to `game/GameStatus.vue` (turn, score, Stop) or, once finished, `game/GameResult.vue` (Settings calls `reset()`, Rematch calls `start()`). The selected dot lives in `Game.vue` and reaches the board through `v-model:selected-dot`.
  - **Computer turn**: `Game.vue` uses `useComputerTurn.ts`, which watches `isComputerTurn` (immediate, so a restored game resumes), waits `COMPUTER_DELAY_MS` and draws `chooseComputerLine(...)` through the normal `drawLine`. Its `isThinking` locks the board and shows "Thinking…"; call `cancel()` on Stop, Rematch and Settings.
  - **Rules panel**: the header's info button (`App.vue`) opens `src/shared/components/RulesPanel.vue`, a modal side panel rendered once in `App.vue` around `GameRules.vue` (both are app shell, so they live in `shared/`; full screen below `sm`, closed by default, ✕/backdrop/Esc, focus trapped and returned to the info button). No screen shows rules inline. Its open state is the module-level `useRulesPanel()` composable (`src/shared/composables/`); `Game.vue` passes it to `useComputerTurn` as a pause reason next to the Stop dialog (VR-31). The rules text in `GameRules.vue` must match the spec (RL-5).
- **Native (Android) touches** (`src/native/`): `main.ts` imports `@capacitor/core` and it dynamically, only when `__CAPACITOR_BUILD__` (a compile-time flag `vite.config.ts` defines from the build mode, declared in `env.d.ts`) is true and `Capacitor.isNativePlatform()`, so the web build contains no Capacitor code (check `dist/assets` after a Pages build). Each plugin call catches its own failure, so one failing call doesn't stop the others. It handles the back button (rules panel, then the Stop dialog via the module-level `useStopDialog()`, then `App.exitApp()`; AR-3) and paints the status bar from `--wc-paper` as the theme changes (AR-4). At launch it asks Google Play for an update (`@capawesome/capacitor-app-update`, `app-update.ts`; AR-20): Play's own flexible prompt, and once downloaded `completeFlexibleUpdate()` installs it and restarts the app (the game is restored from storage). Only Play-installed builds see updates. Android 15+ is edge-to-edge and ignores the background, so the page runs under the system bars (`viewport-fit=cover` in `index.html`): give the app shell and every full-screen `fixed` layer `p-safe-N` (padding N plus the safe-area insets, `styles.css`) instead of `p-N`. Specs fake the Capacitor plugins with `vi.mock` and call `startNative()` after mounting. Icon and splash sources live in `assets/`, written by `npm run generate-icons`; `npm run android:assets` turns them into Android resources (AR-5).
- **Persistence**: `Game.vue` writes the whole game to localStorage under `CURRENT_GAME` (`src/static/storage-keys.ts`) in a `watchEffect`, going through `StorageService` (`src/services/storage.service.ts`, which JSON-serializes objects). On load, `Page.vue` reads it back with `getItem(key, { applyParse: true })` and rehydrates it via `dotsAndBoxesGame.reset(savedGame)`. `GameSetup.vue` also saves `GAME_MODE` and `DIFFICULTY` when a game starts and reads them when setup opens. `useTheme` saves `THEME`.
- **Models** (`src/models/`): `DotsAndBoxesGame`, `Dot`, `Line` and `Square` are classes. Each has a `Partial<Self>` constructor that doubles as the JSON rehydrator: it builds nested `Line`/`Dot`/`Square` instances and defaults with `??`, so 0-based `row`/`col` survive. Chainable `setX()` setters return `this`. `reset(game?)` does `Object.assign(this, new DotsAndBoxesGame(game))`, which keeps the same reactive object identity. When adding fields, update the constructor so that restoring from storage keeps working.
  - Game rules live on `DotsAndBoxesGame` (`isValidStartDot`, `validNeighbors`, `canDraw`, `drawLine`, `stop`, `start`, `winner`). `lines` is the single source of truth for drawn edges, and `dirtySquares` holds only owned squares.
  - `gameMode` (`'twoPlayers' | 'computer'`, missing in old saves → Two players) and `difficulty` (`'easy' | 'normal'`, only in computer mode) live on the game; `isComputerTurn` and `legalMoves()` serve the computer player.
  - Ownership is tracked by player **name** (`ownerName`, `getPlayerByName`), so player names must be unique. The setup form enforces this case-insensitively through a custom `differentFromAll` rule.
  - The computer player is always `player2`, stored under `COMPUTER_NAME` (`computer-player.model.ts`) and never shown: display any player name through `useDisplayName()` (`src/shared/composables/`) or `PlayerName.vue` (adds `RobotIcon`). Its color comes from `computerColorFor()` in `src/utils/computer-color.ts`: the swatch most different from the person's color.
  - `computer-strategy.ts`: `chooseComputerLine(game, difficulty, random)` is pure (Easy: random legal move; Normal: claim, else safe line, else fewest given away). Test it with a fixed random source.
- **i18n** (`src/i18n/`): vue-i18n with the Composition API (`legacy: false`). `locales/en.ts` defines the message keys, and `locales/uk.ts` is typed as `typeof en`, so both must have the same keys. With no saved `LOCALE` the first launch follows the device (`uk` when `navigator.language` starts with `uk`, otherwise `en`; I18N-2, AR-6), and a saved `LOCALE` always wins; `setLocale()` saves `LOCALE` in localStorage and updates `<html lang>`, `document.title` and the `<link rel="manifest">` href (one manifest per language, `src/static/manifests.ts`). All UI text goes through `const { t } = useI18n()`; never hard-code visible strings, and add every new string to both locale files. vee-validate messages come from `configure({ generateMessage })` in `src/i18n/index.ts`, using each `<Field>`'s translated `label`. The language button (one round `BaseIconButton` showing the current language; a tap switches to the other) is `src/shared/components/LanguageToggle.vue` in the `App.vue` header.
- **Theme and styling** (`src/assets/styles.css`): the Warm cream palette is `--wc-*` custom properties, light on `:root` and dark on `:root[data-theme='dark']`, exposed to Tailwind through `@theme inline` as semantic colors (`bg-paper`, `bg-surface`, `text-ink`, `text-ink-soft`, `text-muted`, `bg-accent`, `text-on-accent`, `border-border`, `bg-dot`, `text-danger`, …). Use these tokens, never raw `gray`/`blue`/`white`, so both themes work. `useTheme()` (`src/shared/composables/useTheme.ts`) follows `prefers-color-scheme` live until `toggle()` saves an override under `THEME`, and sets `data-theme` on `<html>`; an inline script in `index.html` applies the same rule before the app loads.
- **Player colors**: `SWATCHES` in `src/utils/swatches.ts` (8 key + hex pairs, keys double as `colors.<key>` i18n keys) and `randomSwatch(except?)`. `PlayerField.vue` renders them as a radiogroup bound to the same `player.color` hex, with a `differentColor` rule in Two players mode. Saved games may hold any hex, so never assume a color is a swatch.
- **Logo and icons**: `src/shared/logo.ts` (`logoSvg()`, `faviconSvg()`) is the one SVG source; `AppLogo.vue` renders it in the header with `currentColor` dots and an animation that respects reduced motion. `npm run generate-icons` (`scripts/generate-icons.ts`) regenerates `public/favicon.*` and the install PNGs after a logo change; commit them. UI icons are inline SVG components in `src/shared/icons/` (Material Symbols Rounded, license in its README); no icon font.
- **Forms**: vee-validate `<Form>`/`<Field>` with string rules (`required|min_value:2|max_value:10`). Rules are registered with `defineRule` inside the component that uses them. Nested field names like `player1.name` map onto the `GameSetupForm` shape.
- **Shared UI** (`src/shared/components/Base*.vue`): Tailwind-styled primitives, including `BaseSegmentedControl` (radiogroup switch for game mode and difficulty). `BaseInput` forwards `$attrs` so it can take vee-validate's `field` binding.
- **Imports**: use the `@/` alias for `src/`. `models`, `services`, `static` and `utils` each have an `index.ts` barrel.

## Conventions

- TS is strict with `noUncheckedIndexedAccess` enabled, so indexed access returns `T | undefined`.
- Linting: oxlint `correctness` category is set to error, and ESLint uses `vue/flat/essential` plus the vue-ts recommended config. Prettier owns formatting (`eslint-config-prettier`).
- Node `^22.18.0 || >=24.12.0`.
